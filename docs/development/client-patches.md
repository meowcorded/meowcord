# Client patches

The test client is Discord's own web client, cached in `assets/cache` by `bun run generate:client`. We change it in three places, and almost everything belongs in the first one.

1. Equicord plugins in `client/plugins`. Equicord is built from a pinned commit and loaded before Discord's bundle, so its patcher rewrites webpack modules as they register. This is where Quests, ads, Nitro and Server Boost upsells, download prompts, the phone browser fixes in FosscordMobileWeb, which keep invite and template links in the browser instead of handing off to the Discord app and let Android browsers join voice, the data collection toggles, instance branding, the verified AI, OFFICIAL and SYSTEM name tags, the app component fixes in FosscordApps, the Go Live quality a browser stream announces to viewers, which FosscordGoLive takes from the capture constraints instead of the client's 4K 120 fps default, the Krisp noise cancellation model URLs, which FosscordCore points at this instance's `/krisp_browser_models` route instead of Discord's CDN, and the browser notification permission prompt, which FosscordNotifications shows when desktop notifications are turned on, and the Server Insights page, where FosscordInsights drops the 500 member minimum and the link to Discord's developer portal and adds charts for members, messages, voice, top channels and invites, are handled. FosscordFrames draws profile frames around the whole side profile in DMs, with room above and below the full-width card for the frame's art, instead of only the frame's top layers squeezed into the profile's footer. FosscordClanBadges adds the instance's own server tag badges (`src/util/util/ClanBadges.ts`, passed to the client as `CUSTOM_CLAN_BADGES`) to the badge picker for every server, in their own sections under the client's badges, one per pack: "Custom Icon Pack" (`CUSTOM_CLAN_BADGE_PACK`) unless a badge names another `pack`, and draws them from their pixel grids in the server's badge colours, the same way the CDN does for tags shown elsewhere. A badge marked `staff_only` is still drawn but left out of the picker, so it can only be given out from the admin panel. FosscordTemplateLinks adds "Have a template link?" to the create server popup: it takes a template link or code, including discord.new and discord.com/template links, shows what the template holds, and creates the server from it. The server looks up codes it doesn't have on Discord's public template API (`templates.allowDiscordTemplates`), and the template preview no longer needs a login, so `/template/<code>` links work for people who aren't signed in. FosscordLimits takes the group DM size from the server (`limits.channel.maxGroupDmRecipients`, passed to the client as `GROUP_DM_RECIPIENT_LIMIT`) instead of Discord's 10. FosscordSounds plays the instance's own ringtone, `assets/public/sounds/call_ringing.mp3`, for incoming calls, including the seasonal and rare variants of the ringtone. FosscordViolations shows what staff wrote about a violation under "You broke the rules for" in its popup on the Account Standing page; the server sends the rule as the violation's description and the staff message in `staff_message`. FosscordApps also gives profile widgets made in the developer portal their own Your Profile Widgets tab in the Add Widget picker, picked by the `owned` flag the server puts on widget configs, and hides the "Link your account to show off your game stats" line on widgets whose application has no account to link. [profile-widgets.md](../features/profile-widgets.md) has the rest. FosscordRoleTemplates adds Member, Moderator, Staff and Manager permission templates above the permission list in the role editor. Each one builds on the one before it, none of them includes Administrator, and picking one replaces the role's pending permissions with the template's, leaving out any the editor can't grant, so it still has to be saved. PlatformSpoofer, which is off by default, lets you appear online from desktop, web, mobile, VR or a console (Discord's embedded platform, sent as an Xbox). It rewrites the browser and os of every IDENTIFY as it goes through `WebSocket.send`, because Discord's fast-connect script, a separate bundle Equicord can't patch, identifies before the app loads. The server picks the platform from those (`getClientPlatform` in `src/util/util/Presence.ts`). Since the presence store ignores updates about yourself, the plugin also answers `getClientStatus`, `isMobileOnline` and `isVROnline` for your own user and adds the platform to the account panel avatar, and while it is on, the phone and headset status shapes stay for idle and do not disturb instead of turning into the moon and minus. Discord has no console shape, so consoles get a gamepad mask added to the client's mask library, and `isVROnline` returns `"console"` for them so they reuse the headset's size and avatar cutout. FosscordModals keeps active dialogs and their popouts above the native backdrop. It lowers inactive native modal layers below that backdrop, so a click outside a nested Change Banner picker reaches the native dismissal handler instead of controls in the settings window beneath it. This preserves the native close callback and keeps color pickers and dropdowns above the backdrop.
2. Static rewrites in `scripts/client.js`. They run once over the cached files, and only cover what has to be fixed before any script runs: the `https:` to `location.protocol` URL fixes, the remote auth URL and the guard that stops Discord from deleting `window.localStorage`.
3. Plain scripts in `assets/client_patches`, injected in name order after Equicord. Only code that doesn't touch Discord's modules lives here: the e2ee loader, the Web Push subscriber described in [notifications.md](../features/notifications.md) and the email verification and QR login pages.

## Building

`bun run build:equicord` runs `scripts/vencord.js`, which:

- checks out `commit` from `client/vencord.json` into `.vencord/src` (override with `VENCORD_DIR`),
- applies the source fixes in `client/equicord-patches/*.patch`,
- copies `client/plugins/*` into Equicord's `src/userplugins`,
- installs dependencies with Equicord's own pnpm (falling back to `corepack pnpm` or `bunx pnpm`),
- builds the web target and writes `assets/vencord/vencord.js`, `vencord.css` and the Monaco files for the QuickCSS editor.

`bun run generate:client` runs it after downloading the client. Both `.vencord/` and `assets/vencord/` are gitignored. `src/bundle/TestClient.ts` serves `assets/vencord` and adds the script right after `GLOBAL_ENV`, so it runs before any Discord code. If the file is missing the client still loads, just without the plugins, and the server logs a warning. The page also leaves out Discord's Sentry bundle and its preload link. Equicord's NoTrack plugin would stop it anyway, but only by throwing an uncaught error on every load. `GLOBAL_ENV.WEBAUTHN_ORIGIN` is set to the page's hostname, which is the relying party ID the server uses for passkeys, so the client's passkey signal calls stop failing with a relying party mismatch.

The default set leaves out every plugin that talks to a third-party service on load or on use (ReviewDB, Decor, Translate, USRBG, ClearURLs, Dearrow and similar), so with the defaults the client only ever contacts this instance. `client/equicord-patches/no-donor-badges.patch` removes core donor badge requests to `badges.vencord.dev` and `badge.equicord.org`. `no-cloud.patch` drops the Cloud settings page and skips cloud settings sync on the web build, since it would talk to `api.vencord.dev` and OAuth against discord.com. `no-donate-card.patch` removes the donation and contributor cards from the Equicord settings tab, which also loaded their images from Discord's CDN. `instance-branding.patch` adds a `brand()` helper to `@utils/types` that swaps Discord for the instance name and subscription labels for Features. `definePlugin` and `definePluginSettings` run every plugin and option description through it, and so do the crash handler toasts and the hardcoded copy in the Equicord, Plugins and Themes tabs. The same patch hides FakeNitro, since every account already has the features it unlocks. `who-reacted-real-channels.patch` stops WhoReacted from fetching reactors for messages outside a real channel, such as the Accessibility preview in channel 1337. `no-silenttype-command.patch` removes the `/silent-typing` command that SilentTyping adds to the slash picker, so the picker only lists Discord's built-ins and app commands. Silent typing can still be toggled from the chat input context menu. A source patch must not add new files, because the build only resets tracked files before it applies the patches again.

`vencord.js` starts with a small script that seeds the default plugin set from the `plugins` and `settings` keys of `client/vencord.json`. A default is applied once per browser and recorded in the `FosscordVencordSeeded` localStorage key, so a user who turns a plugin off keeps it off, and a plugin added to the defaults later still reaches existing users. A plugin's default can also be an object of plugin settings, such as `{ "enabled": true, "isEnabled": false }`. Each distinct object is applied once, so changing it reaches existing users one more time. Our own plugins are `required`, so they can't be turned off.

To move to a newer Equicord, change `commit` in `client/vencord.json`, rebuild and run the check below.

The pinned source is Equicord `1489c0e2a4435d854d7343a5cfb0abb894772318`. The legacy `build:vencord` command, `.vencord` cache, `assets/vencord` URLs and `client/vencord.json` filename remain compatible. Existing browser `VencordSettings` are copied to `EquicordSettings` only when Equicord settings are absent. QuickCSS keeps its existing storage. SilentTyping retains its previous global enabled choice, and new browsers keep typing visible. New-plugin notifications are disabled by default.

The build reads `patches` and `settingsKey` from `client/vencord.json` and points the cached `.vencord` checkout at the configured repository before it fetches the commit. The Docker build bootstraps the exact pnpm version Equicord declares instead of running `bunx pnpm`, and calls pnpm's Node entry point, because pnpm 12 ships a launcher without a shebang when its install scripts are blocked and Bun cannot spawn it.

Custom plugin dependencies listed in `pluginDependencies` are linked from the root Bun installation into the separate Equicord toolchain. `VENCORD_OUTPUT` selects a staging output directory for browser verification before replacing served assets. Build metadata records the source repository and pinned commit.

## Reviewed client releases

`client/release.json` pins the Discord build number, version hash, bootstrap hash after stripping response nonces and the Cloudflare challenge script that the server never serves and SHA-256 digest of every downloaded asset. It contains metadata, not Discord code. `scripts/client.js` checks this pin before publishing a downloaded index. `bun scripts/client-release.js --check` verifies the cached files against the pin. Docker checks it during client initialization and server startup, and the bundled server checks it before serving the client. Missing JavaScript, stylesheets and WebAssembly cannot fall back to an unreviewed upstream response.

For a new build, download into an empty staging directory with `CLIENT_CACHE_PATH=/tmp/meowcord-client-review CLIENT_RELEASE_REVIEW=1 bun scripts/client.js`. The review switch permits a staging download; it does not bypass server verification. Run `CLIENT_CACHE_PATH=/tmp/meowcord-client-review bun scripts/client-release.js --record` to prepare a candidate pin. Run the E2EE anchor check, the Equicord reporter and the full browser encryption test against a disposable server serving that exact staging cache before committing the pin. Keep the download, `release-manifest.json` and generated Equicord assets outside git. A changing upstream build fails the release gate until it has been reviewed.

## Adding a patch

Put it in the plugin that matches what it removes, or create `client/plugins/<name>/index.ts` with an AGPL header and `definePlugin({ name, description, authors: [FosscordAuthor], required: true, patches })`. Shared helpers are in `client/plugins/fosscordCore/shared.tsx`:

- `hideSetting(key)` hides a node of the settings layout by its `SettingsSections` key (`BILLING_SECTION`, `DATA_USAGE_STATISTICS_SETTING`, ...). Pass `{ replacesPredicate: true }` when the node already has a `usePredicate`.
- `hideNotices([...])` turns off notice bars by their `NoticeTypes` name.
- `redirectHome` and `redirectTo(path)` render a redirect, for routes that should not exist.

A patch has a `find`, a string or regex that picks the one module to patch, and one or more `{ match, replace }` replacements. Rules that keep patches working across Discord updates:

- Anchor on things Discord doesn't minify: enum and constant names (`.GUILD_BOOSTS`, `"nitro-tab-group"`), analytics names, route names, intl message hashes.
- Write minified identifiers as `\i`. Never put a minified name such as `tk.n` in a `find` string, use a regex `find` instead.
- A string `find` must only occur in the module you want. Equicord applies a patch to the first module that contains it and then drops the patch, so a second module with the same text makes the real target silently unpatched.
- Reference translated strings as `#{intl::KEY}`, or as `#{intl::HASH::raw}` when only the hash is known. Search `assets/cache` for the English text to find the hash.
- Never match hashed CSS class names like `container__5287f`. They change on every Discord build.
- Prefer removing an element where it is created, `null&&` in front of a `jsx(...)` call works well, over hiding it with CSS.

`bun run build:equicord` rebuilds, and with `NODE_ENV=development` the server reloads the page source on the next request. A patch whose `match` finds nothing logs `Patch by <plugin> had no effect` to the browser console.

## Checking patches after a Discord update

`bun run check:client` builds Equicord's reporter variant and runs `scripts/vencord-check.mjs`. It needs a running server (`ORIGIN`, default `http://localhost:$PORT`) and `playwright-core` (from the repo or `~/.cache/fosscord-tools`). The check opens `/login` in headless Chrome with the reporter build in place of the normal one. The reporter enables every Equicord plugin, loads every lazy chunk, runs every lazy webpack lookup and logs each patch that matched no module, had no effect or threw. The check script adds the one case the reporter skips, a patch marked `all` whose `find` matches no module at all.

The output groups problems into our plugins, upstream plugins in our default set and the other upstream plugins. It exits with code 1 when either of the first two groups has a problem or the reporter never finishes, so a Discord update that breaks a patch fails loudly. The full result is written to `assets/vencord/report.json`. A run takes one to four minutes.

Google Chrome 154 on macOS quits headless sessions after about 30 seconds. Point `CHROME_PATH` at another Chromium build, for example `CHROME_PATH="/Applications/Brave Browser.app/Contents/MacOS/Brave Browser"`.

`settings-router.patch` drops the `USER_SETTINGS_MODAL_KEY` lookup from `SettingsRouter`. Discord no longer exports that key, and the lookup broke `Ctrl+,` in WebKeybinds and the settings links in BetterSessions and Decor.

`webkit-webpack-origin.patch` keeps Equicord's webpack origin lookup on direct `/assets/<bundle>.js` paths. WebKit includes the Equicord setter itself in error stacks, so taking the first asset path selected `vencord/vencord.js` and failed to exclude the libdiscore bootstrap. That initialized Equicord against libdiscore's module cache and crashed registration before Cap mounted. The patch skips the nested Equicord path and recognizes the caller bundle in both WebKit and Chromium stacks. Run `ORIGIN=http://localhost:<port> BROWSER=webkit bun scripts/dev/cap-signup-smoke.mjs` on an isolated instance to check the native signup form, proof expiry, registration and one-use proof replay in WebKit with an iPhone viewport.

`web-screen-share-without-display-media.patch` lets Equicord start in browsers that cannot capture the screen. Equicord's WebScreenShare plugin bound `navigator.mediaDevices.getDisplayMedia` when its module loaded. Safari on iOS and iPadOS and the Android browsers do not have that function, and a page served over plain HTTP from another host has no `navigator.mediaDevices` at all. The bind threw while the bundle was starting, before any plugin registered its patches, so those browsers ran the unpatched client: no Cap verification on the signup form, no pride flag picker and none of the other plugins. The patch binds the function only when it exists and leaves the plugin idle otherwise. Desktop WebKit and Chromium's phone emulation both have the function, so `cap-signup-smoke.mjs` removes it from its phone contexts.

RoleColorEverywhere, StickerPaste and BetterRoleContext stay out of the default set, because Discord shows none of these by itself: it doesn't color member list role headers or user mentions, and it sends a sticker as soon as it is picked from an empty message box.

The checker starts the reporter once webpack is ready if Discord does not call its startup hook. Diagnostics from disabled upstream plugins are informational.

Run `bun scripts/client.js --check` to verify the cached asset dependency closure without downloading or changing files. Run `bun scripts/dev/client-worker-smoke.mjs`, then repeat with `BROWSER=webkit`, to start cached worker bootstraps that contain importScripts and a webpack runtime map. The probe serves only the local cache on an ephemeral loopback port, blocks external HTTP requests and observes each worker for one second before terminating it. It checks initial imported chunks and startup errors; it does not exercise feature-specific worker messages or assets fetched later by those features. `CLIENT_CACHE_PATH` selects an alternate snapshot.

Run `bun run typecheck:equicord` to check the pinned upstream compiler and all injected plugins without building or publishing client assets. It applies the same source patches and plugin dependencies as the web build. Library checking stays enabled. Two dependency patches remove legacy WebCodecs type references because the supported TypeScript compiler already provides those DOM declarations; the media-capture track declarations remain loaded.

Run `PORT=<port> TEST_ACCOUNT_PATH=<isolated-seeded-account-file> bun scripts/dev/equicord-toast-smoke.mjs`, then repeat with `BROWSER=webkit`, to verify the role-template success toast in the native client. It creates and deletes an owned server and role, renders the existing plugin component and checks that applying the draft leaves stored permissions unchanged until Save.

## Branding

These `client.*` config keys control what the client shows in place of Discord's brand:

| Key            | Default      | Used for                                                                                                                                                                              |
| -------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `instanceName` | `"Meowcord"` | Every translated string, the page title, the wordmark and the authenticator app issuer.                                                                                               |
| `icon`         | `null`       | Square icon on the Home button, the loading screen, the wordmark, the login QR code and the favicon. Falls back to `general.image`, then to the built-in vector of `assets/icon.png`. |
| `logo`         | `null`       | Wordmark on the login, register, OAuth and invite pages. Without it the wordmark is the icon followed by `instanceName`.                                                              |
| `helpUrl`      | `null`       | Where the `?` button and every Discord help center link go. Without it the button and standalone help links are hidden, and help links inside a sentence render as plain text.        |

`icon` and `logo` take an `http(s)` URL or a file path relative to the repository root, such as `assets/logo.png`. The server serves the icon at `/static/logo.png`, the path the status and admin pages already use, and the wordmark at `/static/wordmark`. It passes their URLs to the client as `GLOBAL_ENV.INSTANCE_ICON` and `INSTANCE_LOGO`, next to `INSTANCE_NAME` and `HELP_URL`. The page is rendered again when any of these change.

Emails use the same branding. Every HTML email is headed by the `logo` wordmark, or by the icon followed by `instanceName` as text when no wordmark is set. Gmail and Outlook do not draw SVG, so emails load their images from `/static/email/icon.png` and `/static/email/wordmark.png`. Both serve a configured PNG unchanged and convert any other format to PNG with sharp, fitting the icon inside 144 pixels and the wordmark inside 800 pixels. Without sharp, or when the conversion fails, they serve the configured image as it is. The wordmark image carries `instanceName` as styled alt text, so a mail client that blocks images still shows the name.

### Strings

`FosscordBranding` wraps every translation module in `brandMessages` (`client/plugins/fosscordBranding/messages.ts`), which walks the compiled message tree and rewrites only the text, never argument names, tag names or link targets. It replaces Discord with the instance name, subscription branding with Features, `discord.gg/` with this instance's `/invite/` URL and `discord.com` with its host. It handles the inflected forms the translations use: Finnish and Croatian case endings, Hungarian `Nitró` forms, Czech `Nitra` and `Nitru`, Turkish apostrophe suffixes, the Thai and Japanese transliterations and the uppercase `DISCORD`. It leaves the Crisis Text Line keyword (`Text DISCORD to 741741`) and email addresses such as `privacy@discord.com` alone. A few hardcoded strings outside the translations get their own patches: the document title, the platform name list and the `otpauth://` issuer used for authenticator apps. The OAuth consent page drops the joke scope Discord adds to the list at random, such as "Solve a mystery with Scooby and the gang", so it only lists the scopes the app asked for.

### Images

Some Discord logos are image files, not React components, so the server swaps them. `src/bundle/TestClient.ts` serves `/favicon.svg` (and the legacy `/assets/favicon.ico` URL) from the configured instance icon or the supplied adaptive Meowcord favicon, and `BRANDED_ASSETS` replaces the wordmarks on the login, register and invite pages (`131c318dd45b7aa4.svg`, and `bbbc3d376d38e7bc.svg` in the narrow layout) and the logo in the centre of the login QR code (`dd05fd1ea37e7747.png`) with SVGs drawn from the instance icon and `client.instanceName`, or redirects to `client.logo` when it is set. The file names change when Discord updates the client, so after `bun run generate:client` open `/login` and check that both images still show the instance logo. The logo in the app itself, on the Home button, the Direct Messages title and the soundboard category, comes from `FosscordBranding`, which swaps the path of Discord's logo icon. The default glyphs use the exact head and whisker paths from the supplied `meowcord-logo.zip`. The native favicon badge manager restores the adaptive favicon when its unread badge clears, so its canvas reset does not freeze the default artwork to one theme. Unread badges continue to render over the instance favicon. The three original SVG files live in `assets/public/branding`; `assets/icon.png` is the supplied purple app tile exported as PNG, and generated default avatars use the monochrome glyph rather than the opaque app tile. Default PWA icons resize that tile directly. Configured instance icon and wordmark overrides still take priority.

`FosscordBranding` and `FosscordLoading` share the supplied spinner: the 1.1-second flip and both whisker flares retain the archive's paths, keyframes and timing. The archive's reduced-motion selector is strengthened to match the whisker selectors' specificity, so reduced motion disables all three animations. The admin dashboard's per-instance `LOADING_SVG` override still takes priority, and custom loading tips remain independent of the default animation. `bun scripts/dev/branding-smoke.mjs` checks the rendered archive paths and animation, reduced motion, custom SVG/tip priority, adaptive favicon, default avatar eye holes and the PWA tile pixels against a running local instance; use `BROWSER=webkit` for WebKit. The home screen icons and the web app manifest come from the server too, see "Installing to the home screen" in [deploy.md](../self-hosting/deploy.md#installing-to-the-home-screen).

### Default avatars

The client's `DEFAULT_AVATARS` point at `/embed/avatars/0.png` to `5.png` on this instance's CDN. `bun run build:src` runs `scripts/default-avatars.js`, which uses sharp to cut the instance icon out of six coloured squares and writes them to `dist/default-avatars`. It reads the icon from `DEFAULT_AVATAR_ICON`, then from `client.icon` or `general.image` in the file at `CONFIG_PATH` when that is a local path, then from `assets/public/branding/meowcord.svg`. Without sharp the CDN draws the same avatars as SVG.

### Free features and profile gradients

Feature entitlements retain Discord's internal `premium_type` fields for compatibility. Profiles omit subscription tenure and subscription badges, and the admin user editor has no subscription selector. Staff badges and pride badges stay visible.

The native Profiles color section includes **Show profile gradient**. Turning it off sets pending theme colors to `null`; turning it back on restores the pair chosen during that editing session. The native **Save Changes** button persists both settings. The toggle controls your global profile. Server profile colors keep their existing inheritance behavior.

## Client scripts

`55-simple-signup.js` takes the email and date of birth fields out of the signup form. It leaves the email field and its required check in place when `GLOBAL_ENV.REGISTER_EMAIL_REQUIRED` is true, which `src/bundle/TestClient.ts` sets from `register.email.required`. [signup.md](../features/signup.md#email) describes the setting.

`60-auth-pages.js` uses a native modal dialog for email verification and remote-auth decisions. The browser keeps the background inert and restores prior focus on close. Content replacement focuses the next action, and an explicit zero tab index makes buttons reachable in WebKit keyboard mode. Escape cancellation is prevented and outside clicks do not dismiss these required results. [The HTML dialog specification](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element) defines native modal focus behavior. The portal and encryption factories already use native dialogs and retain their own close callbacks.

`66-native-dialog-scroll.js` locks document scrolling while any native modal dialog is open, including authentication and encryption dialogs. The lock remains after child dismissal and ends after the last modal closes; pre-existing inline locks remain untouched. Required dismissal and scrolling inside long encryption dialogs keep working.

The homepage includes the fixed Meowcord project credit directly in its HTML. `src/bundle/TestClient.ts` includes the same credit outside the client mount and loads `assets/public/meowcord-credit.js` to show it on login and hide it after navigation into the app. This script does not touch webpack. The credit is independent of Equicord settings and instance branding, with no disabling setting.

The composer handles the expected HTTP 429 with code 20016 from slowmode without an unhandled rejection, keeps the failed message for the Resend message action and cleans up the draft as usual. Other send failures still reject.

[dialog-dismissal.md](dialog-dismissal.md) lists how each owned dialog and popover dismisses and how the developer portal handles late responses.
